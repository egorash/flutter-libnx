# План: покрытие нативных возможностей для игр

Цель — чтобы можно было сказать «игровое приложение на Flutter работает на
Switch» не потому, что один конкретный заголовок запустился, а потому что
закрыты всё, на что игра по-настоящему натыкается.

План составлен по измерениям, а не по списку популярных пакетов. Раздел
7 объясняет, почему список популярных пакетов здесь не подходит.

---

## 1. Критерий «поддержано»

Приложение считается поддержанным, если при его запуске на консоли не
происходит ни одного из трёх событий:

1. на канал, которого у порта нет, приходит `MissingPluginException`;
2. игра продолжает работать в фоне после потери фокуса;
3. приложение опирается на возможность, которой на Switch нет, и получает
   выдуманные данные вместо честного отказа.

Первый пункт измерим: в журнале есть строка
`unbekannter Kanal -> MissingPluginException`. Второй и третий — нет.

## 3. Ярус 0 — каналы самого фреймворка

**Это не сторонние плагины, это каналы Flutter. Их зовёт любое приложение.**

Измерено: в прогоне `romashka_game` четыре канала фреймворка не имеют
обработчика — `flutter/platform`, `flutter/keyboard`, `flutter/navigation`,
`flutter/isolate`.

Через `flutter/platform` проходят вызовы, которые игра зовёт сама либо
зовёт её фреймворк:

| Вызов | Что делает | Нужен игре |
|---|---|---|
| `SystemChrome.setPreferredOrientations` | блокировка ориентации | да — вызывается через `get` |
| `SystemChrome.setEnabledSystemUIMode` | полноэкранный режим | да — вызывается через `flame` |
| `HapticFeedback.vibrate` | вибрация | да, игры зовут часто |
| `SystemSound.play` | щелчки интерфейса | желательно |
| `Clipboard.setData` / `getData` | копирование счёта, кода | желательно |
| `SystemNavigator.pop` | кнопка «назад» | желательно |
| `System.initializationComplete` | признак готовности | уточнить |

`flutter/keyboard` — сырые события клавиш (имя игрока, чат).
`flutter/isolate` — фоновые изоляторы, которые зовут некоторые пакеты.
`flutter/navigation` — внутренний канал маршрутов; на практике приложение
живёт и без него, но каждый вызов даёт исключение.

**Почему это первым.** Это дешёво (в основном однострочники), это
блокирует любое приложение независимо от его плагинов, и это единственный
ярус, где «не работает» бьёт по всем сразу.

## 4. Ярус 1 — жизненный цикл приложения

**Для игры это важнее большинства плагинов.**

Измерено: порт отправляет Dart `AppLifecycleState.resumed` ровно один раз
при старте и больше ничего. `SwitchPlatform::PollEvents()` отслеживает
только `appletMainLoop()` и касания; состояние фокуса applet не
отслеживается вовсе.

Что из этого следует:

- **Игра не знает, что её свернули.** При сворачивании HOME, уходе в сон
  или вызове системного applet приложение продолжает считать кадры.
- **Аудио не останавливается.** Наш аудиопоток крутится сам по себе; музыка
  продолжается, пока фокус потерян.
- **Обычный игровой код это не ловит.** `didChangeAppLifecycleState` с
  паузой — стандартная практика, но без события обработчик не сработает.

Что нужно:

1. Ловить уведомление applet о потере фокуса (через `appletHook` либо
   состояние, которое `appletMainLoop` уже потребляет).
2. Отправлять `AppLifecycleState.paused` при потере и `resumed` при
   возврате.
3. Останавливать аудиопоток при паузе и продолжать с того же места.
4. Заодно: `appletMainLoop()` сейчас вызывается дважды за кадр — в раннере и
   в `PollEvents`. Это стоит проверить, дублирование уведомлений applet
   может быть отдельной ошибкой.

## 5. Ярус 2 — несколько игроков

Сейчас порт видит только один источник ввода: игрок 1 либо встроенные
джой-коны в портативном режиме. Для игры это означает, что:

- локальный multiplayer на Switch невозможен в принципе;
- при подключении Pro Controller в доке вторая пара геймпадов не появится.

Что нужно:

1. Перечислить `HidNpadIdType_No1..No8` плюс `Handheld`, не ограничиваясь
   одним.
2. Дать каждому свой `gamepadId` — плагин `gamepads` и адресует устройства
   по нему.
3. Развести вибрацию по устройствам: сейчас дескрипторы запрашиваются для
   одного id.

Пакет `gamepads` поддерживает несколько устройств штатно, порт — нет.

## 6. Ярус 3 — честные заглушки

Решение заказчика: пакетам, у которых на Switch нет аналога, отвечать
честно, а не исключением.

Обоснование из опыта `audioplayers`: когда канал не отвечает, Dart
получает исключение на каждом вызове. В одном прогоне это дало одиннадцать
тысяч исключений и семь мегабайт протокола. Честный ответ сохраняет
работоспособность приложения и не подсовывает выдуманных данных.

Разделение на два вида:

**Отвечаем правдой:**

| Пакет | Ответ |
|---|---|
| `connectivity_plus` | всегда «подключено» — у консоли нет API статуса сети |
| `permission_handler` | всегда разрешено — на Horizon нет модели разрешений |
| `battery_plus` | если applet отдаёт заряд, иначе честный отказ |
| `device_info_plus`, `package_info_plus` | подставляемые значения, документированные |

**Честно отказываем:**

| Пакет | Почему |
|---|---|
| `flutter_local_notifications` | уведомлений в homebrew нет |
| `in_app_purchase` | магазина нет |
| `bluetooth_plus`, `nfc_plus` | публичного API нет |
| `camera`, `geolocator` | камера недоступна, GPS отсутствует (есть только позиционирование по Wi-Fi) |
| `connectivity` реальные измерения | сеть не измеряется |

Каждая заглушка обязана быть зарегистрирована явно и возвращать
осмысленное значение. Молчаливый `null` хуже отказа: приложение
продолжит работу с выдуманными данными.

## 7. Почему не по списку популярных пакетов

Первый вариант плана был построен так: взять частые пакеты и закрыть их.
Заказчик указал, что `url_launcher` и `image_picker` для игр не нужны —
они полезны мобильным приложениям.

Это правильное уточнение, и оно меняет метод. Игра зовет:

- `flame` — физика, рендер, аудио, ввод: всё либо уже есть, либо чисто
  Dart;
- `get` — маршрутизация и `SystemChrome`;
- `flame_audio` → `audioplayers` — сделано;
- `flame_gamepads` → `gamepads` — сделано;
- `shared_preferences` — сохранения, сделано;
- `compute()` — 11 вызовов в `romashka_game`, работает через
  `dart:isolate`, канала не требует.

Чего игра не зовёт принципиально: камера, геолокация, буфер обмена в
рекламе, покупки, уведомления. Список «частых пакетов приложений» к таким
приложениям отношения не имеет.

Поэтому план строится от того, что **обязано работать у любой игры**, а не
от того, что популярно у мобильных клиентов.

## 8. Порядок работ и приёмка

| Шаг | Что | Критерий приёмки |
|---|---|---|
| 1 | Каналы фреймворка, ярус 0 | в протоколе нет строк `unbekannter Kanal` |
| 2 | Жизненный цикл, ярус 1 | при потере фокуса Dart получает `paused`, аудио замолкает |
| 3 | Несколько игроков, ярус 2 | `listGamepads` возвращает два id, кнопки адресуются раздельно |
| 4 | Заглушки, ярус 3 | каждая зарегистрирована явно и отвечает осмысленно |

Шаги независимы, кроме того, что проверка приёмки каждого требует
рабочего приложения на железе.
