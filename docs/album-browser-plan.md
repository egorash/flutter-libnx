# План: браузер фото из Альбома Switch для `image_picker` (ветка `album-picker`)

Статус: черновик плана. Дата: 2026-10-11.
Ветка: `album-picker` (от `master` форка).

Контекст: `image_picker` в `my_nexus` сейчас отдаёт **самое свежее** фото из
папки-импорта `/switch/flutter_apps/<app-id>/import/` (см.
`docs/plugin-plan-my-nexus.md`, обработчик `HandleImagePicker`,
`plugins_horizon.cpp:773`). Заказчик: (1) источник фото — **только Альбом**
консоли `/Nintendo/Album/**`, копирование руками не нужно; (2) нужен
**выбор конкретного снимка** — полноценный браузер делаем сейчас.

---

## 1. Цель и рамки

- `image_picker.pickImage(source: gallery)` открывает **браузер снимков из
  Альбома** консоли, пользователь выбирает снимок, приложение получает его
  путь и показывает (как сейчас, `Image.file(path)` на стороне `my_nexus`).
- Источник — `/Nintendo/Album/ГОД/МЕСЯЦ/ДЕНЬ/*.jpg` на SD (проверено на
  консоли: `/Nintendo/Album/2026/03/25/*.jpg`). Папка-импорт как механизм
  больше не нужна.
- `my_nexus` не меняем; правки — в эмбеддере и генерируемом регистранте.
- Отмена выбора → `null` (текущий «отменённый» путь протокола, визард
  `MediaPickerSheet` его спокойно переживает).
- Видео (`.mp4`) Альбома не показываем — только изображения.

## 2. Что уже есть в эмбеддере (базис)

| Блок | Где | Что даёт |
|---|---|---|
| EGL/GLES + резолв GL-функций | `platform/egl_horizon.cpp` (`flutter_libnx_egl_resolve`) | доступ к GL из эмбеддера |
| Хук на растёр-потоке перед `eglSwapBuffers` | `egl_horizon.cpp` (виртуальный курсор) | можно рисовать оверлей поверх кадра |
| Внешние текстуры / кадровый колбэк | `engine/media_kit_video_horizon.cpp` | образец вывода текстур в Skia |
| Ввод: pad + touch + виртуальный курсор | `platform/switch_platform.cpp` | управление геймпадом и тачем |
| Генерация регистранта `horizon_main.dart` | `scripts/build-dart-app.sh:113-140` | точка инъекции Dart-шима |

Вывод: оба варианта (ниже) технически опираются на уже существующие
механизмы, новых системных зависимостей не требуется.

## 3. Два варианта архитектуры

### Вариант A — Dart-шим (рекомендуется)

```
Dart (app) my_nexus (не трогаем)
   │  ImagePicker().pickImage(source: gallery)
   ▼
Dart-шим (генерируется build-dart-app.sh, examples/<app>/generated/)
   HorizonImagePickerPlatform (ImagePickerPlatform.instance)
      -> полноэкранный маршрут: сетка Image.file из /Nintendo/Album/**
   │  отвечает app-стороне выбранным путём (или null)
   ▼
C++ (embedder) — только ответ на канал plugins.flutter.io/image_picker
```

- Рендер сетки, декод JPEG, скролл, фокус — средствами Flutter
  (`Image.file`, `GridView`), C++ почти не нужен.
- Управление геймпадом — через уже существующий виртуальный курсор +
  тач; при необходимости — маппинг крестовины на фокус.
- **Риск:** маршрут нужно вставить в корневой `Navigator` чужого
  приложения (`my_nexus` использует свой роутинг). Найти его можно через
  `WidgetsBinding.instance.rootElement` → обход дерева → `NavigatorState`.
  Это единственная неочевидная точка — проверяем **спайком** на Этапе 1.

### Вариант B — нативный оверлей

- Сетку миниатюр рисуем сами GL-квадами в пре-swap хуке растёр-потока,
  декод JPEG — сторонним декодером (`stb_image`, один заголовок), ввод,
  скролл и выделение — вручную.
- Плюс: не трогаем дерево приложения. Минус: много кода (шейдеры,
  текстуры, лейаут, скролл, выделение) и выше риск.

**Решение:** идём вариантом **A**; если спайк покажет, что корневой
`Navigator` недоступен/нестабилен — переходим к **B**.

## 6. Риски

- **Корневой Navigator чужого приложения** (вариант A) — главный риск;
  спайк Этапа 1 обязателен, откат к варианту B продуман.
- **Альбом на внутренней памяти** (нет SD) — путь может отличаться;
  проверить на железе, иначе честный `null`.
- **Производительность** декода больших JPEG при скролле — миниатюры +
  кэш; лимит одновременных декодов.
- **GL-потокобезопасность**: Mesa не терпит параллельную отправку из двух
  потоков (см. `media_kit_video_horizon.cpp:19-44`) — оверлей/текстуры
  только на растёр-потоке.
- **Объём Dart-шима** — контролируется обзорами на этапах.

## 7. Критерии приёмки

- `image_picker` берёт фото **только из Альбома**; копирование руками не
  нужно, папка-импорт не задействована.
- Пользователь **выбирает конкретный снимок**; путь возвращается, приложение
  показывает выбранное фото.
- Отмена → `null`, визард `my_nexus` не ломается.
- Управление: геймпад + тач.
- Нет крашей/«Another exception», приемлемый FPS.
